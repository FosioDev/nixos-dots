# sound.nix

Конфиг `92-low-latency` содержит настройки для минимальной задержки в играх по типу `osu!stable` через wine. quantum устанавливает размер буфера (чем меньше значение, тем ниже задержка, но выше нагрузка на процессор). Можно посчитать теоретическую задержку в секундах, поделив quantum на rate (48/48000 будет 1мс). Если со звуком есть проблемы (щелчки, прерывания), попробуй увеличить значение (64, 128, 256) или просто удалить эту настройку.

Число в имени настроек определяет приоритет настройки.

Мой конфиг запрещает редактировать звук любому приложению, кроме `pavucontrol` и `easy effects`. Потому что звонилки по типу зума и дискорда клали хуй на мои настройки громкости микрофона и просто принудительно делают его тихим, и меня никто не слышит. Для pipewire настройка применяется через скрипт в конфиге. Для браузеров надо сделать руками:
- Firefox based - открываешь `about:config` и делаешь `media.getusermedia.agc_enabled false`. Это Automatic Gain Control
- Chromium based - открываешь `chrome://flags/` и делаешь `Allow WebRTC to adjust the input volume = Disabled`

Чтоб разрешить ещё одному приложению менять звук:
- В терминал `wpctl status`, найти нужное приложение в списке клиентов
- Потом `wpctl inspect номер-клиента | grep application.process.binary`
- Добавляешь в конфиг по шаблону новый процесс и ребилдишь
- `systemctl --user restart wireplumber pipewire pipewire-pulse`

# home-manager

Мне не нравится делить конфиг на модули `native nixos` и `home-manager` как два разных каталога. Потому что будет несколько разных `zsh.nix` и прочих файлов в разных каталогах. Поэтому я сделал алиас `hm.` для всех параметров `home-manager` и теперь можно вызывать настройки native nixos и home manager в одном файле.

Нормальный алиас на `hm` делается таким импортом на самом верхнем уровне (`configuration.nix`):
```nix
  imports = [
    # Alias. Использовать через `config.hm.параметр`
    (lib.mkAliasOptionModule [ "hm" ] [ "home-manager" "users" username ])
  ];
```

# Приколы с переменной `config`

Если в конфиг файле надо использовать разом обычный параметр, и параметр с началом `config.`, то будут ошибки. Лучшим вариантом будет добавить `config` в импорты сверху и это походу добавит `config.` перед каждым параметром. То есть `config.my.colors` или `config.hm` больше писать не надо, можно просто `my.colors` и `hm.services`. Иначе ошибки будут. Но с таким импортом LSP будет светить "не используется, удали". Если `config.` надо добавить не у параметра, а у его значения, тогда пишешь полный путь `background = config.my.colors.base00`.

# Описание `system.stateVersion`

Какое значение стоит изначально в твоей системе, то ставишь и в мой конфиг. Например, старая система используется с версии 24.05, её и надо ставить. А при установке с нуля на новую систему надо будет ставить 26.05, это последняя версия на данный момент.

# Если софт из внешнего flake input компилируется

Если вместо скачивания бинаря начинается компиляция софта, то проблема в бинарном кеше. Если это софт от самого nixos, то ничего не поделать. Если это происходит с внешним flake input, например `nix-gaming`, то проблема в том, что надо руками добавить новое зеркало с бинарным кешем. Это делается через `nix.settings` в `packages.nix`. Возможно надо будет удалить пакет из этого flake input, добавить бинарный кеш, ребилдить, и лишь после ребилда с новым кешем добавлять пакеты, иначе всё равно компилировать будет. Обычно в readme для нового flake input говорят как добавить новый кеш.

# Способ дебажить параметры

Запустить конфиг в виртуалке (не тестил):
```sh
nix run .#nixosConfigurations.nixos.config.system.build.vm
```

Узнать параметр home-manager из flake.nix получилось так:
```sh
nix eval --impure .#nixosConfigurations.nixos.config.home-manager.useGlobalPkgs --json
```
Узнать параметры в самом конфиге я смог так:
```sh
nix eval --impure --json .#nixosConfigurations.nixos.config.home-manager.users.fosio.параметр
```
Например, вот узнал включен ли home-manager (если ошибка, значит не указана такая настройка и она не имеет дефолта походу)
```sh
nix eval --impure --json .#nixosConfigurations.nixos.config.home-manager.users.fosio.programs.home-manager.enable
```

Вывести все цвета в формате json
```sh
nix eval --impure .#nixosConfigurations.nixos.config.my.colors --json
```

Эта команда покажет merge всех пакетов системы и иногда светит синтаксические ошибки в конфиге, если они есть:
```sh
nix eval --impure --json .#nixosConfigurations.nixos.config.environment.systemPackages
```

# Проверить целостность системы

```sh
# Современный (и рекомендуемый) способ — Nix 2.4+ (новый CLI)
nix store verify --all

# Если хотите видеть прогресс и подробности
nix store verify --all --verbose

# Очень тщательная проверка (пересчитывает хэш каждого файла внутри каждого пути)
nix store verify --all --check-contents

# Только текущую систему (гораздо быстрее)
nix store verify /run/current-system

# Начать починку
nix store verify --all --repair
```
